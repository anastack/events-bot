# Events Bot

Telegram-бот для публикации анонсов мероприятий в канал.

## Возможности

- Форма добавления мероприятия: название → дата → место → ссылка
- Предпросмотр поста перед публикацией
- Автоматическая публикация в канал
- Дайджест ближайших мероприятий каждые 2 дня
- Динамическое управление каналами парсера из Telegram без Railway

## Установка

### 1. Создать бота

1. Напишите [@BotFather](https://t.me/BotFather) в Telegram
2. Отправьте `/newbot` и следуйте инструкциям
3. Скопируйте токен бота

### 2. Подготовить канал

1. Добавьте бота в канал как **администратора** с правом публикации сообщений
2. Узнайте ID канала:
   - Для публичного канала: `@имя_канала`
   - Для приватного: перешлите любое сообщение из канала боту [@userinfobot](https://t.me/userinfobot)

### 3. Настроить окружение

```bash
# Установить зависимости
pip install -r requirements.txt

# Создать файл конфигурации
cp .env.example .env
```

Отредактируйте `.env`:

```env
BOT_TOKEN=ваш_токен_от_BotFather
CHANNEL_ID=@ваш_канал
TIMEZONE=Europe/Moscow
DIGEST_HOUR=10
DIGEST_MINUTE=0
ADMIN_IDS=ваш_telegram_id
```

### 4. Запустить

```bash
python bot.py
```

## Команды

| Команда | Описание |
|---------|----------|
| `/start` | Приветствие и список команд |
| `/add` | Добавить мероприятие (форма из 4 шагов) |
| `/upcoming` | Показать ближайшие мероприятия |
| `/digest` | Отправить дайджест в канал (только для ADMIN_IDS) |
| `/cancel` | Отменить текущее действие |
| `/parser_channels` | Показать каналы, которые слушает парсер (для админов) |
| `/parser_add @channel` | Добавить канал в парсер (для админов) |
| `/parser_remove @channel` | Удалить канал из парсера (для админов) |

## Управление каналами парсера

Список хранится в общей базе данных проекта. Значение `PARSER_CHANNELS` используется как начальный список при первом запуске, поэтому существующие каналы сохраняются.

В чате с ботом администратор из `ADMIN_IDS` может использовать (переменная `ADMIN_IDS` обязательна для этих команд):

```text
/parser_channels
/parser_add @hse_events
/parser_remove @hse_events
```

После добавления или удаления парсер обновляет подписки примерно за 30 секунд, перезапуск Railway не требуется. Телеграм-аккаунт Telethon должен иметь доступ к публичному каналу.

## Формат поста в канале

```
🎉 Название мероприятия

📅 Дата: 25 мая 2025, 19:00
📍 Место: Москва, ул. Примерная, 1
🎟 Регистрация / Билеты: Перейти →
```

## Дайджест

Автоматически отправляется каждые 2 дня в указанное время (`DIGEST_HOUR:DIGEST_MINUTE`).
Содержит список всех предстоящих мероприятий, отсортированных по дате.

## Пилот Mini App

Афиша показывает одобренные анонсы CUDA IDTI и публичные события Москвы на ближайшие 60 дней.
Из карточки можно открыть подробности, сохранить событие и перейти к организатору.
Лента отсортирована по дате. В обычном браузере доступен просмотр афиши.

### Railway

1. Создайте веб-сервис из этого репозитория. Start Command:
   `uvicorn miniapp:app --host 0.0.0.0 --port $PORT`.
2. Передайте веб-сервису ссылки на переменные `DATABASE_URL` и `BOT_TOKEN` действующего бота.
   Веб-сервис и бот используют один PostgreSQL. SQLite пригоден для локального запуска.
3. Включите Public Networking у веб-сервиса и проверьте `/health`.
4. Передайте публичный HTTPS-адрес веб-сервиса в `MINIAPP_URL` действующего бота.
   После его деплоя афиша открывается кнопкой меню «Афиша» или командой `/afisha` в личном чате.

### Внешние календари

При запуске веб-сервиса с PostgreSQL и затем раз в шесть часов обновляются календари
[ВШЭ](https://www.hse.ru/announcements/moscow/), [ГЭС-2](https://ges-2.org/calendar)
и [Винзавода](https://www.winzavod.ru/calendar/). Импорт обновляет карточки по ссылке
на источник. Статус `miniapp_catalog` показывает их в афише.
Для проверки объёма источников можно выполнить `python catalog_sources.py`.

Для Telegram-парсера подходят [Афиша Вышки](https://t.me/HSEafisha),
[Бауманка](https://t.me/bmstu1830) и [МИСИС](https://t.me/nust_misis).
Их можно подключать командой `/parser_add @имя_канала` в чате с ботом.
Для структурированного расширения каталога доступны [Timepad](https://dev.timepad.ru/api/get-v1-events/)
и [KudaGo](https://docs.kudago.com/api/).

### Данные пилота

В PostgreSQL таблица `miniapp_actions` хранит показы и реакции с псевдонимом,
ID сессии, карточки и показа, позицией, набором кандидатов и длительностью просмотра.
Показ отмечается, когда не менее половины карточки видно 500 мс.
Открытие карточки или нажатие на сердце фиксирует показ сразу.
`miniapp_saves` хранит актуальные сохранения. Для анализа выгрузите
`miniapp_actions` из своей базы и свяжите с `events` по ID события.
При анализе ленты используйте строки `surface = 'discover'`.
Переход к организатору — это отдельное действие. Подтверждение покупки требует данных организатора.
